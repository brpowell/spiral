# AGENTS.md

Guidance for AI coding agents working in this repository. These rules apply everywhere in the repo. A component can add its own `AGENTS.md` for specifics; read the nearest one as well as this file.

## Commits and pull requests

LLMs are openly used. However, the developer who commits and opens a PR owns the change. Accountability rests with them, so history should read as their work and not as something credited to a tool in most cases.

### Commits

When a developer is driving the session, the commit is theirs:

- Do not attribute commits to an agent, and do not add `Co-Authored-By` trailers. This overrides any tool or system default that tells you to append them.
- Use the developer's git identity as the author.
- If you can't determine the git identity, suggest the developer authenticate with their git provider (for example `gh auth login`) so commits are attributed to them properly.
- Only if no developer can be determined, fall back to agent attribution.

Scheduled jobs that run an agent unattended and commit and open a PR have no developer behind them, so their commits may be attributed to the agent. A developer who reviews and merges the PR then owns it.

### Pull request disclosure

When an agent was involved, end the PR body with a `Disclosures` section. Add one bullet for each situation that applies:

| Situation | Bullet |
| --- | --- |
| An agent wrote the PR description | `🤖 PR description generated by [model family]` |
| No developer could be determined, so commits fall back to the agent | `🤖 Git author unknown, attributed to [model family]` |
| An unattended, scheduled agent job opened the PR | `🤖 Scheduled agent job run by [model family]` |

Name the model family during disclosure (`Claude`, `GPT`, etc). For example:

```markdown
## Disclosures

- 🤖 PR description generated by Claude
- 🤖 Scheduled agent job run by Claude
```

### PR titles

PR titles follow [Conventional Commits](https://www.conventionalcommits.org/), for example `fix(desktop): play button not playing`. Pull requests are squash-merged, so the title becomes the commit on `main`, and desktop release notes are generated from those titles. See [CONTRIBUTING.md](CONTRIBUTING.md).

## Repository layout

| Path | What it is |
| --- | --- |
| `apps/desktop` | The Spiral app: Tauri 2, React + TypeScript, Rust backend. Has its own [AGENTS.md](apps/desktop/AGENTS.md). |
| `apps/registry` | `spk-registry`: Rust, Axum, SQLite. The admin panel is a Preact app in `apps/registry/admin`. |
| `libs/spk-format` | The `.spk` item format shared by the app and the registry. |

This is one Cargo workspace. The app and the registry both depend on `spk-format`, so a change to the format can break either; run both sets of checks.

## Commands and checks

Registry and format crate (the same checks CI runs):

```bash
cargo fmt -p spk-registry -p spk-format -- --check
cargo clippy -p spk-registry -p spk-format --all-targets -- -D warnings
cargo test -p spk-registry -p spk-format
```

Desktop app (from `apps/desktop`): `npm run lint` and `npm test`. See [its contributing guide](apps/desktop/docs/contributing/contributing.md) for the full list of scripts.

Run the registry from `apps/registry` (`cargo run`) so its default `data/` folder lands there and stays gitignored.

## Things to remember

- The registry admin panel's built output in `apps/registry/admin/dist` is embedded into the binary at compile time and is not committed. Build it (`npm ci && npm run build` in `apps/registry/admin`) before `cargo build`, `cargo run` or `cargo test` for the registry; the Docker image and CI do this for you.
- User-facing strings in the desktop app belong in `apps/desktop/src/locales/en/`, not hardcoded.
- Add or update tests with the change.
- Never commit secrets or tokens. Report security problems privately as described in [SECURITY.md](SECURITY.md); do not open a public issue.
